## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Hook script execution (CC harness → user's shell) | Every UserPromptSubmit and SessionStart fires a bash script in the user's environment. Even stub scripts run in the user's shell with the user's env. |
| Plugin source resolution (marketplace `source` → filesystem) | The marketplace.json entry (added by Plan 02) points at this directory via relative path. Future ownership of the marketplace ref determines what tree gets installed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | hooks/scripts/session-start.sh, nudge.sh | mitigate | Phase 1 scripts emit ONLY static text via `cat <<'EOF'` (single-quoted heredoc suppresses any expansion). They do not read stdin, do not exec subcommands, do not source any external file. Phase 3 will introduce stdin reads and grep; Phase 3 plan must add an explicit "MUST NOT exec untrusted content" gate. Phase 1 surface area: zero dynamic input. |
| T-01-02 | Denial of Service | Hook script execution path | accept | UserPromptSubmit fires on every prompt (matcher ignored in CC 2.1.x per RESEARCH Pitfall 3). Cost = one `cat` + heredoc per prompt. Single-digit milliseconds. Timeout 3s in hooks.json is two orders of magnitude above worst case. Accepted: heavy scripts would matter but stubs are <10 lines. |
| T-01-03 | Information Disclosure | hook scripts (stdout → Claude context) | accept | Stub scripts emit Phase-marker text only. No env vars dumped, no file paths exposed, no PII. Accepted: zero-leak by content design. |
| T-01-04 | Repudiation / Audit | Hook firing events | accept | No audit logging in Phase 1 (mechanism spike only). Phase 3 may add structured stderr for `claude --debug` visibility. Accepted: stub-only scope. |
| T-01-05 | Elevation of Privilege | Hook script trust | mitigate | Hooks run with user's shell privileges by design (Claude Code architecture). Phase 1 mitigation: scripts contain no `sudo`, no privileged calls, no writes outside stdout. The +x bit is set ONLY on the two intended scripts (Task 4 scope is explicit). |
| T-01-SC | Tampering | Package supply chain | n/a | RESEARCH §"Package Legitimacy Audit" confirms zero npm/pip/cargo dependencies. All files are hand-authored. No third-party packages in this plan. |
