# Plan 03-01: Author Full Marketplace Manifest

## Objective

Render `02-CLASSIFICATION.json` into the canonical `.claude-plugin/marketplace.json` covering all topical buckets, then validate against ROADMAP Phase 3 success criteria.

## Approach

Phase 3 is mechanical translation — every decision is locked upstream:

- **Group taxonomy & skill membership** — Phase 2 `02-CLASSIFICATION.json` (D-13 bucket-keyed shape with drop-in `skills` arrays).
- **Source declaration** — `source: { source: "git-subdir", url: "https://github.com/yaklang/hack-skills.git", path: "skills" }` (ROADMAP SC #3; corrected from `source: github` after Phase 1 research).
- **Schema** — `strict: false`, root-level `./<skill>` paths (Phase 1 D-03-REVISED).
- **Naming** — `hack-skills-<bucket-key>` (ROADMAP SC #2).
- **Description** — the bucket's verbatim `description` field from `02-CLASSIFICATION.json`.

Generate the file programmatically via `jq` so the result is derived, not hand-edited.

## Open Decision: `hack-skills-routers`

Phase 2 explicitly flagged this bucket for Phase 3 to resolve (see `02-CLASSIFICATION.md` § `hack-skills-routers` — "Whether this bucket should be exposed as its own marketplace plugin OR excluded from `marketplace.json` entirely is a Phase 3 question").

**Decision: exclude** the `hack-skills-routers` bucket from `marketplace.json`.

**Rationale:** PROJECT.md grouping axis — *"Group by skill-content topicality, NOT by yaklang's own categorization. Skills that don't map to any topical bucket probably shouldn't have a group at all."* The router skills (`api-sec`, `auth-sec`, `business-logic-vuln`, `file-access-vuln`, `hack`, `injection-checking`, `recon-for-sec`) are the upstream's own categorization layer, not topical playbooks. They served their purpose for Phase 2's D-07 every-skill-assigned invariant; they do not earn a marketplace plugin.

This yields **13 marketplace plugins** from the 14 Phase 2 buckets (14 − 1 routers).
